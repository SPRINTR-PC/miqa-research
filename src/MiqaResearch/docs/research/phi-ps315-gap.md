# PHI tags left in place vs. DICOM PS3.15 Annex E

Ticket: [#204](https://github.com/SPRINTR-PC/miqa-research/issues/204) (map #176). Date: 2026-09-24.

## Question

What does `PHI_TAG_KEYWORDS` (`MiqaResearch/tasks/dicom_handling/phi.py`) leave in place, compared with the PS3.15 Basic Application Level Confidentiality Profile and its options? Which of the survivors does the viewer / SUV need?

## Sources

- **[S1]** DICOM PS3.15 **2026d**, Annex E, Table E.1-1 (Application Level Confidentiality Profile Attributes). Parsed from the DocBook source: `https://dicom.nema.org/medical/dicom/current/source/docbook/part15/part15.xml`, table `table_E.1-1`: 657 rows.
- **[S2]** PS3.15 §E.1.1 (Basic Profile requirements), §E.3.6 (Retain Longitudinal Temporal Information), §E.3.10 / Table E.3.10-1 (Retain Safe Private), same file.
- **[S3]** `MiqaResearch/tasks/dicom_handling/phi.py` and `metadata_dump.py` on `main` at 2fac3e9.
- **[S4]** `cornerstonejs/calculate-suv` `src/types.ts` (`InstanceMetadata`), GitHub HEAD.

Method: map each E.1-1 tag to a pydicom keyword, then diff with `PHI_TAG_KEYWORDS`. Each survivor is grouped by the **first** option column that retains or cleans it. A survivor with no option column is a pure Basic-Profile gap: no option allows it to stay.

## Answer

- `PHI_TAG_KEYWORDS` = **19 tags**, all in E.1-1 [S3][S1]. **638 of the 657** E.1-1 rows survive: 537 current and 101 retired.
- Today's behaviour is roughly Basic Profile **plus** Retain Full Dates + Retain Device Id + Retain Institution Id + Retain Patient Characteristics + Retain Safe Private (in fact *all* private tags) + no Clean Descriptors / Structured Content / Graphics. It also has **153 current tags that no option retains**. Those are real gaps against any conformant profile.
- `metadata_dump.py` pseudonymizes only 5 UIDs (Study/Series/SOPInstance/MediaStorageSOPInstance/FrameOfReference) [S3]. The other **45 UID-bearing tags** in the Retain UIDs group keep their original values. Examples: `ReferencedSOPInstanceUID`, `ReferencedFrameOfReferenceUID`, `SourceImageSequence`, `ReferencedStudySequence`, `IrradiationEventUID`, `DimensionOrganizationUID`, `ConcatenationUID`, `PyramidUID`. Those values are re-identifiable against the source PACS, and they break referential consistency with the rewritten UIDs.
- **Private tags survive whole.** The dump keys them as `GGGG,EEEE` and never filters them [S3]. The Basic Profile removes all private tags unless Retain Safe Private is used, and that option keeps only the Table E.3.10-1 list [S1][S2].
- §E.1.1 also requires `PatientIdentityRemoved` (0012,0062)=`YES` plus `DeidentificationMethod`/`...CodeSequence` [S2]. Neither is set today.

### Viewer / SUV needs (all survive today)

calculate-suv needs `PatientWeight`, `SeriesDate/Time`, `AcquisitionDate/Time`, `RadiopharmaceuticalStartTime` or `...StartDateTime`, `RadionuclideTotalDose`, `RadionuclideHalfLife`, `CorrectedImage`, `Units` and `DecayCorrection`. It also uses `PatientSize` + `PatientSex` for SUL, `FrameReferenceTime`/`ActualFrameDuration` for Siemens, and the Philips/GE private groups [S4].

| Tag | E.1-1 Basic | Option that keeps it |
|---|---|---|
| PatientWeight (0010,1030), PatientSize (0010,1020), PatientAge (0010,1010) | X | Rtn. Pat. Chars. **K** |
| PatientSex (0010,0040) | Z | Rtn. Pat. Chars. **K** |
| Study/Series/Acquisition/Content Date+Time, AcquisitionDateTime | X/Z/D | Full Dates **K**, Modified Dates **C** |
| RadiopharmaceuticalStartTime (0018,1072), ...StartDateTime (0018,1078) | X | Full Dates **K**, Modified Dates **C** |
| RadionuclideTotalDose, RadionuclideHalfLife, Units, CorrectedImage, DecayCorrection, PixelSpacing | not in E.1-1 | always kept |
| Philips PET private (7053,xx00) SUVScaleFactor, (7053,xx09) | private | in Table E.3.10-1 (Safe Private) |
| GE `GEMS_PETD_01` (0009,xx0D) post-injection DateTime | private | **not** in Table E.3.10-1, so a conformant profile removes it |

§E.3.6 explicitly says date/time modification must not "disrupt computations … such as comparison of start of injection time to the acquisition time for PET SUV" [S2]. So **Retain Longitudinal Temporal Information with Modified Dates** (a consistent per-participant shift) is compatible with SUV. Full dates are not required.

## Implication for the viewer

A profile of **Basic + Retain Patient Characteristics + Retain Longitudinal Temporal (Modified or Full Dates) + Retain Device Id / Institution Id (optional) + Retain Safe Private** keeps everything the viewer and calculate-suv need. The one exception is the GE private post-injection time (0009,xx0D). calculate-suv uses it as the scan time only when SeriesDateTime is later than the earliest AcquisitionDateTime, which happens with re-processed GE series [S4]. That case needs a local safe-private exception, and a Modified Dates shift must also apply to that private DT. Moving to it would remove the 153 gap tags, all non-safe private tags, and the unpseudonymized UIDs, with no viewer impact.
